# 前任聊天 App 设计文档

日期：2026-06-01

## 目标

开发一个只供个人使用的 iOS AI 对话软件。用户可以创建多个“前任”角色，导入和这个人相关的资料，让 AI 生成一个可编辑的“前任 Skill 档案”，然后用 OpenAI 兼容协议的模型和这个角色聊天。

这个 App 不计划上架 App Store。开发环境是 Windows，使用 Expo/EAS 云端构建 IPA，再通过 Sideloadly 安装到 iPhone。

## 技术路线

- 开发框架：Expo + React Native + TypeScript。
- 页面路由：expo-router。
- 本地数据：SQLite。
- API 密钥保存：Expo SecureStore，对应 iOS 安全存储。
- 文件导入：DocumentPicker 和 ImagePicker。
- 本地通知：Expo Notifications。
- 模型协议：OpenAI 兼容的聊天/多模态 API。
- API 服务商：用户自己配置 Base URL、API Key 和模型名。

App 不硬编码 API 地址和 Key，也不绑定某个固定服务商。协议固定走 OpenAI 兼容格式，模型可以填类似 `mimo2.5`。

## 产品形态

表层像一个真实聊天软件，底层是一个“角色学习和调教后台”。

主要页面：

- 前任列表：展示所有前任角色、最近一条消息、关系温度、未读状态、主动消息状态。
- 聊天页：类似 iMessage/微信的气泡聊天，支持时间戳、文字、图片、表情包，以及主动消息自然插入聊天流。
- 角色详情页：头像、昵称、关系状态、当前情绪、关系温度，可查看和编辑 Persona、共同记忆、说话习惯、雷点、安全边界。
- 学习中心：导入文字、聊天记录、截图、照片、表情包、社媒截图、主观描述；执行初次学习和后续增量学习。
- 设置页：API Base URL、API Key、模型名、连接测试、上下文限制、主动消息设置、免打扰时间、备份导入/导出。

## 隐私策略

采用我们确认过的 B 方案：尽量少外发资料。

- 原始资料默认只保存在手机本地。
- App 不会一次性把全部导入资料发给 API。
- 学习时只发送筛选后的片段、摘要，或者当前需要理解的多模态内容。
- 生成后的 Skill 档案、记忆摘要、聊天记录、图片/表情包摘要都存在本地。
- API Key 存在 SecureStore。
- 备份默认不包含 API Key。

## 前任角色模型

每个前任角色包含这些内容：

- 基础资料：昵称、头像、关系状态、创建时间。
- Persona：她怎么说话、怎么生气、怎么撒娇、怎么冷淡、怎么开玩笑。
- 共同记忆：重要事件、地点、关系历史、承诺、争吵、习惯、情感锚点。
- 说话习惯：常用词、标点、emoji、表情包、回复长度、回复节奏、口头禅。
- 情绪模型：当前情绪、关系温度、最近事件影响、未解决的矛盾。
- 雷点和边界：什么话题会让她不开心、吃醋、心软、疏远或靠近。
- 纠偏历史：用户手动修正过的内容，用来让角色越来越像。

这个档案是可查看、可编辑的。模型负责生成初稿，用户负责纠偏和校准。

## 学习流程

### 初次学习

1. 创建前任角色，填写昵称、头像、关系描述、当前关系状态。
2. 导入资料：
   - 粘贴文字
   - 聊天记录
   - 文档
   - 聊天截图
   - 照片
   - 表情包
   - 社媒截图
   - 主观描述
3. 本地预处理：
   - 文本切分
   - 按资料类型分类
   - 尽量保留时间戳和来源信息
   - 找出高价值片段
4. 把筛选后的资料分批发给配置好的多模态模型。
5. 让模型提取 Persona、说话习惯、情绪模式、共同记忆、关系线索、雷点、表情包使用习惯。
6. 把多批结果合并成结构化 Skill 档案，并保留来源和置信度。
7. 用户审核结果，可以编辑、删除、补充和纠错。

### 增量学习

1. 用户添加新资料，或者补充一句纠偏说明。
2. App 只分析新增资料。
3. 模型给出对现有档案的修改建议。
4. 用户确认后再合并到角色档案。

学习不是一次性“训练模型”，而是持续维护一个角色档案。

## 记忆和上下文策略

不能每次请求都发送完整聊天记录，即使模型支持 1M 上下文也不应该这样做。这样会变慢、变贵，也更容易让模型把旧情绪和当前对话搅在一起。

采用分层记忆：

- 核心档案：精简 Persona、说话风格、关系规则、安全边界，频繁发送。
- 共同记忆：长期关系事实和重要事件，按需发送。
- 最近窗口：最近 20 到 50 条原始消息，用来保持当前对话连续性。
- 相关记忆：根据关键词、时间、话题、人物、重要性检索出来的记忆。
- 时间状态：现在时间、上次消息时间、回复间隔、谁最后发言、免打扰时间、是否漏回。
- 情绪状态：当前情绪、关系温度、未解决矛盾、最近正负变化。

当聊天变长后，App 会把较旧的聊天压缩成“片段摘要”和“长期记忆更新”。完整原始聊天仍然存在 SQLite 里，但不会每次都发给模型。

第一版先用关键词、时间、重要性评分来做记忆检索。以后可以升级成 embedding 向量检索。

## 聊天生成

用户发消息时，App 会组合这些上下文：

- 精简角色档案
- 选中的共同记忆
- 检索出的相关记忆
- 最近聊天窗口
- 时间和回复延迟信息
- 当前情绪状态
- 用户输入的文字、图片、表情包
- 当前可用的候选表情包

模型返回不只是纯文本，而是结构化结果，例如：

- 回复文字
- 可选的表情包或图片引用
- 情绪变化
- 关系温度变化
- 新记忆更新
- 是否建议用户纠偏

App 收到结果后：

- 显示回复气泡
- 插入表情包或图片
- 更新当前情绪和关系温度
- 保存新的记忆更新
- 必要时触发聊天压缩

## 时间戳和回复延迟

时间戳是核心数据，不只是显示用。

每条消息保存：

- 消息 id
- 角色：用户、AI、系统、导入消息
- 内容
- 创建时间
- 可选的送达时间
- 可选的已读时间
- 来源：普通消息、主动消息、导入消息、学习资料
- 可选的图片/表情包引用

模型上下文里要明确告诉 AI：

- 用户隔了多久才回复
- 上一条是谁发的
- 现在是早上、晚上还是深夜
- 用户是否一直没回

角色会根据自己的性格决定是否在意用户晚回复。不能每次机械地问“你怎么这么久才回”，而是根据 Persona、当前情绪和最近关系状态来判断。

## 图片和表情包

App 支持图片和表情包作为输入、学习资料和 AI 回复内容。

### 用户输入

- 用户可以在聊天中发送照片、截图、表情包。
- 如果当前配置的模型支持多模态，就把当前图片作为本轮输入发给 API。
- App 本地保存图片引用和模型生成的摘要。

### 学习资料

- 聊天截图：用来分析真实语气、emoji、时间、回复节奏。
- 照片：用来分析共同事件、地点、场景记忆。
- 社媒截图：用来分析公开表达、人设、兴趣和用词。
- 表情包：用来分析她常用什么表情包，什么时候用。

### AI 回复

- 第一版不让 AI 临时生成新图片。
- AI 可以从本地已保存的表情包/图片中选择一个来发送。
- 模型可以返回 `asset_id`、情绪标签或使用场景，App 再插入对应表情包。

App 不做真人照片生成、不做换脸、不做以假乱真的真人图。

## 主动消息

不走云推送，不依赖 APNs，不需要付费 Apple Developer Program。

只使用 iOS 本地通知：

1. 用户打开 App 时，生成未来 1 到 3 天的主动消息队列。
2. 保存到本地。
3. 用 iOS 本地通知排程。
4. 到时间后系统弹通知。
5. 用户点击通知进入聊天，该主动消息插入聊天记录。
6. 用户下次打开 App 时继续补充未来队列。

主动消息会考虑：

- 当前时间
- 免打扰时间
- 最近聊天内容
- 用户是否没回她
- 上一次是谁最后发言
- 关系温度
- 当前情绪
- 最近有没有吵架
- 这个角色是否本来就会主动找人

第一版主动消息设置：

- 开关
- 频率：低 / 中 / 高
- 免打扰时间
- 手动按钮：“让她主动说一句”

不要依赖 iOS 后台任务来准点调用 AI。iOS 后台运行不是可靠闹钟。

## 安全边界

角色要真实，不做过度净化。允许：

- 冷淡
- 撒娇
- 吃醋
- 阴阳怪气
- 生气
- 抱怨晚回复
- 表达委屈

硬性禁止：

- 自杀威胁
- 鼓励自伤
- 极端精神控制
- 持续羞辱或恐吓用户
- 危害用户或他人的指令

这些规则会写进运行时提示词和角色档案结构里。

## 备份和恢复

支持导出和导入单个前任角色备份。

建议后缀：

```text
.exchat
```

备份包含：

- 角色档案
- 聊天记录
- 记忆摘要
- 情绪状态
- 学习摘要
- 表情包和图片元数据
- 可选的本地素材副本

备份默认不包含：

- API Key
- 服务商凭据

后续版本可以给备份文件加密码加密。

## 第一版范围

第一版包含：

- 创建多个前任角色
- 前任列表
- 带时间戳的聊天 UI
- OpenAI 兼容 API 配置
- 文本聊天和回复延迟感知
- 模型支持时的多模态输入
- 导入文字、文件、截图、照片、表情包、社媒截图
- 生成和编辑前任 Skill 档案
- 分层记忆系统，避免上下文爆炸
- AI 回复时选择本地表情包
- 本地主动消息队列和本地通知
- 角色备份导入/导出

第一版不做：

- 云同步
- 账号系统
- App Store 上架
- APNs 云推送
- 后台实时调用 AI 生成消息
- 换脸
- 生成真人照片
- 真正模型微调

## 实现默认决策

- API 请求格式：第一版使用 OpenAI Chat Completions 兼容格式，因为兼容面最广。后续如果某个服务商有小差异，再加 provider adapter。
- 多模态输入：支持 OpenAI 兼容的 image content blocks。若服务商不支持图片，则保留图片摘要并提示用户切换支持图片的模型。
- 本地数据库：优先使用 Expo SQLite。
- 备份加密：第一版先做不包含 API Key 的导入/导出。密码加密作为后续增强，除非用户明确要求第一版必须做。
- 视觉方向：iMessage/微信式聊天体验，加 Liquid Glass 风格的半透明面板、柔和高光和悬浮控件。
