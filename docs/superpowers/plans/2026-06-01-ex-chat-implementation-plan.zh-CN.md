# 她聊天 App 实现计划

日期：2026-06-01

## 阶段 1：项目脚手架

- 使用 Expo + TypeScript 创建项目。
- 配置 expo-router。
- 配置基础目录结构：
  - `app/` 页面路由
  - `src/components/` 通用组件
  - `src/features/` 业务模块
  - `src/lib/` API、数据库、工具函数
  - `src/theme/` Liquid Glass 风格主题
- 安装第一批依赖：
  - expo-router
  - expo-sqlite
  - expo-secure-store
  - expo-document-picker
  - expo-image-picker
  - expo-notifications
  - expo-file-system
  - expo-blur
  - expo-linear-gradient
  - react-native-reanimated
  - lucide-react-native

验收标准：

- 项目能在 Expo 中启动。
- TypeScript 能通过基础检查。
- 路由能进入主要页面占位。

## 阶段 2：基础 UI 和视觉风格

- 做出 Liquid Glass 风格基础组件：
  - 玻璃面板
  - 玻璃按钮
  - 顶部栏
  - 底部输入栏
  - 聊天气泡
  - 表情包/图片消息气泡
- 补充基础动效：
  - 页面切换保持轻盈
  - 聊天气泡入场动画
  - 玻璃按钮按压反馈
  - 主动消息插入时的轻微浮现
  - 关系温度和情绪变化时的柔和过渡
- 实现页面骨架：
  - 她列表
  - 聊天页
  - 角色详情页
  - 学习中心
  - 设置页
- 保持聊天页像 iMessage/微信，不在聊天页显示调试标签。

验收标准：

- App 第一屏可用。
- 页面之间可以跳转。
- UI 在手机尺寸下不重叠、不溢出。

## 阶段 3：本地数据库和数据模型

- 使用 SQLite 建表：
  - ex_profiles
  - messages
  - memories
  - assets
  - learning_sources
  - proactive_messages
  - app_settings
- 实现数据库初始化和迁移。
- 实现基础 CRUD：
  - 创建她的角色
  - 读取角色列表
  - 保存聊天消息
  - 保存角色档案
  - 保存素材和摘要

验收标准：

- 创建角色后重启 App 数据仍存在。
- 聊天消息能持久化。
- 数据访问层不直接散落在页面组件中。

## 阶段 4：API 配置和 OpenAI 兼容客户端

- 设置页支持填写：
  - API Base URL
  - API Key
  - Model
- API Key 保存到 SecureStore。
- 实现连接测试。
- 实现 OpenAI Chat Completions 兼容客户端。
- 支持文本消息和多模态 image content blocks。
- 处理常见错误：
  - Key 错误
  - Base URL 错误
  - 模型不存在
  - 网络失败
  - 响应不是 JSON

验收标准：

- 设置页能保存和读取配置。
- 连接测试能给出明确结果。
- 聊天页能通过配置的模型拿到回复。

## 阶段 5：聊天体验

- 实现聊天列表和消息发送。
- 支持：
  - 文字消息
  - 图片消息
  - 表情包消息
  - text + sticker 回复
  - 时间戳显示
- 请求模型时带上：
  - 角色档案
  - 最近消息窗口
  - 回复延迟
  - 当前时间
  - 当前情绪和关系温度
- 模型返回后更新：
  - 消息记录
  - 情绪状态
  - 关系温度
  - 记忆候选

验收标准：

- 能进行一轮完整对话。
- 晚回复信息会进入模型上下文。
- AI 回复能保存并展示。

## 阶段 6：学习中心

- 支持添加学习资料：
  - 手动文本
  - 文件
  - 图片
  - 聊天截图
  - 表情包
  - 社媒截图
- 对学习资料做本地登记和分类。
- 实现初次学习：
  - 分批发送素材摘要或选中素材
  - 生成 Persona、共同记忆、说话习惯、雷点、表情包习惯
- 实现增量学习：
  - 只分析新增资料或纠偏说明
  - 生成修改建议
  - 合并进角色档案

验收标准：

- 能导入资料并保存。
- 能生成一份可编辑的角色档案。
- 用户修改档案后能影响后续聊天。

## 阶段 7：记忆系统

- 实现分层上下文：
  - 核心档案
  - 共同记忆
  - 最近窗口
  - 相关记忆
  - 时间状态
  - 情绪状态
- 实现简单检索：
  - 关键词
  - 时间
  - 重要性
- 实现旧聊天压缩：
  - 把旧消息变成 episode memory
  - 提取长期事实和关系变化

验收标准：

- 模型请求不会携带完整历史。
- 长聊天后仍能保留重要事实。
- 上下文构造逻辑可测试、可调试。

## 阶段 8：图片和表情包

- 建立素材库。
- 图片和表情包保存本地 URI。
- 记录摘要、情绪标签、使用场景。
- 聊天时允许 AI 从本地表情包中选择发送。
- 不做真人图生成、不做换脸。

验收标准：

- 用户能发送图片/表情包。
- 学习资料里的表情包能进入候选库。
- AI 回复可以插入本地表情包。

## 阶段 9：主动消息和本地通知

- 实现主动消息队列。
- 设置页支持：
  - 开关
  - 低/中/高频率
  - 免打扰时间
- App 打开时生成未来 1 到 3 天主动消息。
- 用本地通知排程。
- 点击通知后进入对应聊天，并插入消息。
- 支持手动“让她主动说一句”。

验收标准：

- 不依赖服务器和 APNs。
- 本地通知能触发。
- 主动消息考虑未回复、时间和关系状态。

## 阶段 10：备份和构建

- 支持导出单个角色为 `.exchat`。
- 支持导入 `.exchat` 恢复角色。
- 默认不导出 API Key。
- 配置 EAS Build。
- 生成 iOS IPA。
- 给出 Sideloadly 安装说明。

验收标准：

- 角色可以导出和重新导入。
- 项目能触发 EAS iOS 构建。
- 能拿到 IPA 给 Sideloadly 安装。

## 第一轮实现顺序

为了尽快跑通闭环，先实现一个可用骨架：

1. Expo 项目脚手架。
2. 主要页面和 Liquid Glass 基础 UI。
3. SQLite 数据层。
4. API 设置和连接测试。
5. 创建角色和基础文本聊天。
6. 时间戳和回复延迟上下文。
7. 再逐步加入学习中心、图片、表情包、主动消息和备份。

第一轮目标不是一次性做满，而是先让 App 能在 iPhone 上跑起来，并完成“创建她的角色 -> 配置 API -> 开始聊天”的核心闭环。
